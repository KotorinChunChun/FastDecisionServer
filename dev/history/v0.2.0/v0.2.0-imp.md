# v0.2.0 モデル常駐管理と解放承認

## 出典・設計

2026-10-04 のユーザー依頼と TestJeff/dev/history/v0.20.0/v0.20.0-imp.md の共有 API 契約に基づく。導入済みモデルだけを扱い、モデル取得は行わない。実装担当は実サーバーを操作せず、親担当が統合検証と反映を行った。

- model/device 別 LRU 常駐キャッシュを設け、推論・ロード・解放を単一ワーカーで直列化する。
- メモリに余裕がある追加ロードは確認不要。解放が必要なら対象・世代・期限に束縛した一度限りの承認を求める。
- 明示解放と推論経由の切替も同じ検査を通す。OOM 後に無断で別モデルを追放しない。
- 既存 API と loaded 配列を維持し、常駐一覧、許可、状態、構造化エラーを追加する。
- RAM/VRAM 見積は上限保証ではない。実メモリ取得が不能ならロードを拒否し、解放後にも空きを再検査する。
- 管理要求の本文・画像・承認 token は記録しない。

## 実装・検証記録

- backend/management: modelと解決済みdeviceをキーにLRU常駐、モデル固有の選択肢上限、RAM/VRAM別見積、短い状態lock、失敗時の部分モデル清掃。
- server/contracts: GET /models、POST /models/load/unload、旧一覧互換、構造化承認、管理と推論の共有待ち列、healthの実常駐反映。

- 2026-10-04: 専用venvの全unittest 73件成功。従来48件に容量/承認/失敗/期限/API/設定等25件を追加。
- 実モデル重み取得、実サーバー起動・停止、実GPUの複数常駐測定は行っていない。親担当の統合確認へ引き継ぐ。
- メモリ見積は実測による保証ではない。解放後再検査とOOM時の無断追放禁止で安全側に失敗させる。承認した解放が済んだ後にロード失敗した場合、解放対象は未常駐のままとなり、自動復元はしない。
- 専用venvで src/tests のcompileall成功、git diff --check成功。第三者の読み取りレビューでも承認迂回・並行解放・古いtokenによる追加解放は検出されなかった。
